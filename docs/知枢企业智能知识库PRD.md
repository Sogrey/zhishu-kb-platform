## 1. 背景与机会

### 1.1 问题陈述

企业内部知识以制度、手册、费率表、项目文档、扫描件等形式散落在网盘与邮件中。员工提问时面临三类典型失败：

| 失败类型 | 表现 | 业务后果 |
|----------|------|----------|
| **找不到** | 关键词搜不全、语义搜不准 | 重复询问、新人上手慢 |
| **找得到但不可信** | AI 胡答、无出处、新旧稿混答 | 合规风险、错误决策 |
| **找得到但不该看** | 密级文档被低权限用户命中 | 泄密与审计缺失 |

通用「RAG 问答」产品往往只解决「找得到」的一部分，对企业真正关心的**有效期、版本归并、密级过滤、操作可审计、质量可量化**投入不足——而开源主流方案在「知识治理」能力面上普遍缺位。

### 1.2 机会判断

企业内网（5~50 人）场景需要一套可私有化、可离线、数据不出域的知识中枢：既有行业已收敛的检索问答能力（混合检索 → 精排 → 引用溯源），又把**知识治理**做成一级产品能力，而不是运营事后补丁。

知枢以此为切入点：不做「又一个聊天框」，做「企业知识的治理中枢」。

## 2. 产品定位与目标

### 2.1 一句话定位

**知枢**是面向企业内网的 AI 智能知识库平台：文档入库后可语义问答、可溯源引用；并以知识有效期、旧稿归并、密级过滤、审计水印构成治理闭环，让回答「准、新、该看、可查」。

### 2.2 产品原则

1. **治理优先于生成**：过期退休、旧稿不用、无权不存在——在检索层完成，而非靠提示词「假装没看见」。
2. **可解释优先于玄学**：分块可见、检索可测、引用可点、评测可复现；对外不承诺无口径「准确率」。
3. **数据主权**：业务数据、向量、文件、日志、模型均可落本机/本网，支持全离线。
4. **核心精简、扩展可关**：图谱 / 工作流 / 协同编辑为可选增强，默认不绑架主链路。
5. **清洁室独立实现**：功能规格来自通用工程实践与公开能力面；不引入第三方闭源产品源码/SDK；界面与命名自主设计。

### 2.3 产品目标（对应验收）

| # | 目标 | 验收口径 |
|---|------|----------|
| G1 | **端到端可用** | 上传 → 解析 → 索引 → 流式问答 → 引用点开原文，全链路闭环 |
| G2 | **质量可运营** | RAGAS 四指标有基线，夜间回归可看趋势；参数变更可对比跑 |
| G3 | **治理可审计** | 有效期 / 归并 / 密级 / 审计四项动作落地，审计可按人/文档/时间导出 |

### 2.4 目标用户规模与部署形态

- **规模**：单组织 5~50 人共用（POC ≤5 → 主力 10~30 → 扩容 30~50）
- **形态**：Docker Compose 私有化；A/B/C 三档硬件（见技术方案 §7）；默认 zh-CN

## 3. 用户与场景

### 3.1 角色画像

| 角色 | 诉求 | 典型操作 |
|------|------|----------|
| **成员（Member）** | 快速得到可溯源答案 | 提问、看引用、多轮追问 |
| **知识管理员（Librarian）** | 知识「准且新」 | 上传/解析、设有效期、处理归并提示、查看分块与 Hit Test |
| **审计员（Auditor）** | 合规可回放 | 查审计日志、导出涉密访问记录 |
| **管理员（Admin）** | 空间隔离与权限正确 | 建工作区、配角色/密级、切模型、管 API Key |
| **外部调用方**（P1） | 嵌入站内问答 | 用 Open API / Widget 调用绑定助手的对话能力 |

密级（L1~L4）与角色正交：角色回答「能做什么」，密级回答「能不能看」。

### 3.2 核心业务场景

| 场景 ID | 名称 | 描述 | 优先级 |
|---------|------|------|--------|
| S1 | 制度问答 | 员工问「差旅报销标准」，系统仅用现行有效制度回答并附页码引用 | P0 |
| S2 | 扫描件入库 | 纸质纪要扫描 PDF 经 OCR 入库后可检索 | P0 |
| S3 | 新旧制度切换 | 新制度上传后识别旧稿并归并，问答默认不再引用旧稿 | P1 |
| S4 | 费率表过期 | 费率表设置失效日，过期后自动退出检索 | P1 |
| S5 | 密级隔离 | L4 文档对 L2 用户检索「不存在」，审计可回放命中尝试 | P0/P1 |
| S6 | 质量回归 | 金标集夜间跑 RAGAS，看板看 faithfulness 等趋势 | P1 |
| S7 | 站内嵌入问答 | 业务系统嵌入 Widget，走独立 API Key 与配额 | P1 |
| S8 | 图谱增强问答（可选） | 审核通过的实体关系参与检索；异常时降级普通检索 | P2 |
| S9 | 流程自动化（可选） | 画布串联检索/通知节点，事件触发执行 | P2 |

### 3.3 不做的场景（防范围蔓延）

- 多租户公有云 SaaS 订阅与计费
- OEM 贴牌交付体系
- 协同表格 / 幻灯片等办公套件
- 多语言界面（本期仅 zh-CN）
- 对外宣称未绑定评测方法学的「准确率」数字

### 5.2 分模块说明与验收要点

#### 5.2.1 文档摄取与流水线（FR-01 ~ FR-03）

**用户故事**

- 作为知识管理员，我希望拖入一批 PDF/Word/扫描件后看到解析进度，以便确认何时可问答。
- 作为知识管理员，我希望重复文件被秒级识别，避免同一制度多次入库污染检索。

**规则**

- 支持格式：PDF、DOCX、MD、TXT、常见图片、网页 URL（本期基线；后续可扩 Excel 等）。
- 解析路由：印刷体默认高可用引擎；复杂版面/表格走高保真引擎；扫描件先 OCR 再解析。
- 流水线四段：解析 → 分块 → 嵌入 → 入库；失败入可重试队列；解析中间结果可下载供人工核验。
- 分块对管理员可见（标题感知；表格整表成块并标记）。

**验收**

- [ ] 上传 10 份混合格式文档，≥90% 进入可检索状态或给出可理解失败原因  
- [ ] 相同 SHA-256 文件再次上传被拒绝或合并为同一文档记录  
- [ ] 管理员可打开某文档的分块列表与解析结果下载  

#### 5.2.2 检索与问答（FR-04 ~ FR-08）

**用户故事**

- 作为成员，我希望流式看到回答，并能点击引用跳到文档名/页码/原文片段。
- 作为知识管理员，我希望用 Hit Test 看到模型实际读到了什么，以便调优分块或文档。

**规则**

- 混合检索：向量召回 + 中文全文召回 → RRF 融合 → Rerank → **治理过滤**（密级/有效期/现行稿）→ 上下文组装 → LLM 流式生成。
- 提示约束：仅依据给定资料回答；未命中如实说明，禁止编造制度条款。
- 表格命中：注入全表而非碎片（FR-06）。
- 引用四类独立展示：引用库、参考来源、图谱引用（P2）、正文配图（P2 起可逐步完善）。
- SSE 采用块式协议（块开始 / 增量 / 整块替换含 citations / 结束），便于图文与引用结构扩展。

**验收**

- [ ] 同一问题在有资料时回答含至少一条可点击引用；无资料时明确「未找到」类表述  
- [ ] 密级无权文档不出现在引用与 Hit Test 中  
- [ ] Hit Test 可展示注入片段全文及向量/全文两路相关分数（P1）  

#### 5.2.3 知识治理（FR-09 ~ FR-11）——产品核心差异化

**用户故事**

- 作为知识管理员，我希望给费率表设失效日，过期后系统自动不再用它回答。
- 作为知识管理员，我希望上传新制度时系统提示可能是旧稿升级，一键归并后只答新稿。
- 作为审计员，我希望导出谁在何时访问了哪些密级文档。

**规则**

| 能力 | 行为 |
|------|------|
| 有效期 | 文档/片段级 `valid_from` / `valid_to`；定时扫描置退休；**检索 SQL 恒带时间条件**（即使扫描延迟也不泄露过期知识） |
| 旧稿归并 | 入库与现行稿相似度比对：≥0.92 强提示、0.80~0.92 弱提示；完全相同走 SHA 去重；归并后旧稿 `is_current=false`，默认不参与回答，版本链可查 |
| 密级 | L1 公开 / L2 内部 / L3 秘密 / L4 机密；**检索层过滤**——无权用户对文档「不存在」 |
| 审计 | 登录、检索、密级命中、文档管理、归并、密级变更、导出等写审计；可筛选导出 |
| 水印 | 含 L3+ 内容的页面叠加含用户标识与时间信息的动态水印 |

**验收**

- [ ] 将文档 `valid_to` 设为过去时间后，立即不可被检索命中  
- [ ] 归并后同问题引用仅来自现行稿；版本链可在管理端查看  
- [ ] L2 用户提问无法命中 L4 文档（自动化用例）  
- [ ] 审计导出含 who/what/when/ip/doc 等字段  

#### 5.2.4 权限与工作区（FR-12）

**规则**

- 工作区硬隔离：业务数据带 `workspace_id`，跨空间不可见。
- 角色：admin / librarian / auditor / member（可随实施微调命名，权限矩阵须文档化）。
- 密级独立于角色；Open API 助手绑定知识范围与密级上限，外部 Key 权限 ≤ 任一内部用户。

**验收**

- [ ] 用户 A 工作区文档对用户 B（无成员关系）不可见、不可检、不可答  
- [ ] 角色无权操作被 API 与前端双重拒绝  

#### 5.2.5 评测与可观测（FR-13 ~ FR-14）

**规则**

- 维护金标评测集（建议初版 50~100 条：问题 + 期望答案 + 期望命中文档）。
- 夜间跑 RAGAS：faithfulness / answer relevancy / context precision / context recall；看板趋势；参数变更可手动双跑对比。
- 每次问答可关联 Trace（检索各阶段 + 生成延迟/token），支持按会话回放。

**验收**

- [ ] 至少一套评测集可一键/定时跑通并落库  
- [ ] 看板上能看到不少于 7 天的指标点（或等价历史跑次）  
- [ ] 任选一条线上问答可打开对应 Trace（P1）  

**口径约束**：任何对外「准确率」表述必须同时给出：评测集规模、四指标值、评测日期。

#### 5.2.6 开放 API 与嵌入（FR-15）

**规则**

- `Authorization: Bearer zs-…`；一 Key 绑定一助手；可禁用、可设有效期。
- 两级限流：滑动窗口 RPM + 日配额（UTC+8 零点重置）。
- 调用日志：时间/IP/耗时/token，可导出。
- Widget：**禁止 API Key 走 URL Query**；采用短期签名会话换取（如 JWT + PostMessage），降低 Referer/日志泄露面。

**验收**

- [ ] 用官方示例完成多轮 SSE 对话并拿到 citations  
- [ ] 超 RPM / 超日配额返回明确限流错误  
- [ ] 禁用 Key 后立即 401；嵌入场景网络面板中无明文长期 Key  

#### 5.2.7 模型接入（FR-16）

**规则**

- 默认本地推理；控制台可切换模型配置，接入代码无需改。
- P1 增加 OpenAI 兼容云通道；涉密环境可关闭云通道。

**验收**

- [ ] 切换本地模型后新对话使用新模型  
- [ ] 离线开关开启时无外发模型流量（断网冒烟）  

#### 5.2.8 可选增强（FR-17 ~ FR-19）

| 编号 | 产品要求 | 开关与降级 |
|------|----------|------------|
| FR-17 | 实体/关系抽取后须人工审核才参与检索；Hit Test 可见注入三元组 | 默认关；服务异常自动回退普通检索 |
| FR-18 | 画布编排检索/问答/通知；支持事件触发 | 默认关；与同一工作区权限共用 |
| FR-19 | 知识条目富文本共创 | 默认关；不扩展为全套办公 |

启用决策建议：在评测体系建立后，对 FR-17 做 A/B，确认对四指标非负再默认推荐开启。

## 6. 非功能需求

| 编号 | 类别 | 要求 |
|------|------|------|
| NFR-01 | 部署 | Compose 一键拉起；支持全离线冷启冒烟 |
| NFR-02 | 性能（POC） | 单用户问答首 token 可接受（档位相关，A 档以可用性优先）；摄取进度实时可见 |
| NFR-03 | 并发 | 显式配置推理并发预算；≥10 人引导 B/C 档，避免 6GB 显存争用 |
| NFR-04 | 安全 | 内网 TLS 终结；审计只增不改；密级过滤所有检索入口共用同一过滤器 |
| NFR-05 | 许可 | 第三方组件优先 MIT/Apache/BSD/PostgreSQL；**AGPL 零引入**；项目自身 MIT |
| NFR-06 | 可维护 | 模块化单体；关键配置（模型、解析路由、特性开关）可热切换或配置化 |
| NFR-07 | 备份 | 业务+向量+全文同库，一套逻辑备份覆盖；文件卷可独立备份 |
| NFR-08 | 可观测 | P0：推理 slot / 任务队列可观测；规模扩大后再上完整监控栈 |
| NFR-09 | 容量 | 设计目标支撑约百万级 chunks 量级（同档硬件内）；超限有向量引擎迁移预案 |
| NFR-10 | 无障碍/体验 | 管理台信息架构清晰；涉密水印不影响操作；移动端问答可用即可（管理台以桌面为主） |

## 7. 用户旅程与关键交互

### 7.1 主路径：管理员建库 → 成员问答

```mermaid
flowchart LR
  A[创建工作区/邀请成员] --> B[上传文档]
  B --> C[解析完成]
  C --> D[可选: 设密级/有效期]
  D --> E[成员提问]
  E --> F[流式回答 + 引用]
  F --> G[点击引用核验原文]
```

### 7.2 治理路径：新制度替换旧制度

1. 管理员上传新版制度  
2. 系统提示「高度相似现行稿」  
3. 确认归并 → 旧稿退出默认检索  
4. 成员再问同题 → 引用指向新稿  
5. 审计记录归并动作  

### 7.3 信息架构（管理台模块，表达层独立设计）

| 模块 | 主要内容 |
|------|----------|
| 知识库 | 文档列表、上传、摄取进度、分块、解析下载 |
| 对话 | 会话、引用面板、（管理员）Hit Test |
| 治理 | 有效期、归并待办、密级、审计导出、水印策略 |
| 评测 | 评测集、跑次、RAGAS 趋势、Trace 入口 |
| 系统 | 用户/角色/工作区、模型配置、API Key、特性开关 |

界面基于自有设计 token + Ant Design Vue，**不临摹**任何第三方产品视觉与文案。

## 10. 风险、约束与待决事项

### 10.1 产品风险

| 风险 | 影响 | 缓解 |
|------|------|------|
| 复杂版面解析质量不稳 | 表格/分栏问答差 | 路由多引擎；坏文件人工补录；表格还原率纳入验收 |
| 小显存并发体验差 | POC 高峰卡顿 | 档位引导；显式排队；禁止 OCR 与 LLM 抢同一小显存 |
| 图谱增强负收益 | 答非所问 | 默认关；评测 A/B；异常降级 |
| 评测本身耗算力 | 夜间任务挤占 | 低峰跑；小模型抽样子集 |
| 范围蔓延到办公套件/SaaS | 主线失焦 | 本文 §3.3 / §4 硬边界 |

### 10.2 约束

- 仅企业内网私有化；数据不出域为默认承诺。
- 清洁室与许可证纪律见技术方案 §4.3 / §10。
- 商标「知枢」需完成近似检索（第 9/42 类）后再做对外品牌投放。

### 10.3 待评审确认项

1. P2 启用优先序（图谱 / 工作流 / 协同）——建议 M3 后依评测数据决策。  
2. 初版金标评测集的业务来源与标注责任人。  
3. 角色权限矩阵终稿（是否增加「只读访客」等）。  
4. Excel 等格式是否升入 P0 格式基线。  
5. 对外交付是否需要独立「部署手册级」文档作为销售材料（当前竞品常见短板，可作为体验优势）。
